# Клиентский Telegram-бот VUMEXCLUSIVE

Актуальный сценарий: клиент сам открывает отдельного бота. Автоматических сообщений
из личного аккаунта Натальи и автоматических дожимов в личных чатах нет.
Telegram Business остаётся только как необязательный помощник Натальи для ручной
отправки расписания командами `/запись`, `/онлайн`, `/офлайн`.

## Что умеет бот

1. `/start` отправляет одно приветственное сообщение: фирменное изображение с
   редактируемым текстом в подписи и постоянное меню рядом со строкой ввода:
   «Записаться», «Мои занятия», «Цены», «Тренажёр».
2. При навигации бот удаляет предыдущий экран, чтобы чат не превращался в длинную ленту.
   Отдельные напоминания и сообщения о результате оплаты остаются в истории.
3. «Мои занятия» показывает ближайшие подтверждённые записи и брони, по которым
   ожидается чек или его проверка.
4. «Цены» читает активные тарифы из CRM и группирует их по онлайн/офлайн и
   групповым/индивидуальным занятиям.
5. «Тренажёр» показывает сохранённый текст и отправляет загруженное видео.
6. Перед записью бот проверяет подписку на заданный Telegram-канал, если проверка включена.
7. Клиент выбирает онлайн или офлайн.
8. Бот показывает только будущие групповые занятия со свободными местами.
9. После выбора бот фиксирует тариф и сумму из текущего прайса.
10. Место удерживается заданное число минут.
11. Клиент отправляет чек в PDF или фотографией.
12. Данила и Наталья получают чек с кнопками «Подтвердить» и «Отклонить».
13. После подтверждения запись появляется в занятии CRM, а платёж — в финансах.
14. За 3 часа и за 1 час бот присылает напоминание. За час добавляет ссылку
    на онлайн-занятие или адрес офлайн-зала.
15. До нажатия «Старт» Telegram показывает заполненное описание и аватар бота.
16. В канале команда `/закрепить` создаёт фирменный пост с кнопкой «Записаться»
    и закрепляет его. Кнопка открывает бота по ссылке с меткой канала.

## Пост с записью в канале

Бот должен быть администратором канала с правами публиковать, редактировать и удалять
сообщения. После этого администратор публикует в канале одну команду:

```text
/закрепить
```

Бот публикует свой пост с кнопкой «Записаться», закрепляет его и удаляет команду.
Повторная команда заменяет предыдущий пост. Текст поста и подпись кнопки меняются
в CRM в группе «Профиль и пост в канале».

Ссылка имеет Telegram `start`-метку канала. При первом обращении клиент создаётся
или находится по Telegram ID, а в источник записывается `Telegram` и название канала.
Существующий содержательный источник клиента бот не перезаписывает.

## Как определяется цена

- Если у клиента есть действующий групповой абонемент нужного типа, оплата не нужна:
  бот сразу записывает по абонементу.
- Если это первое занятие клиента, используется активный групповой тариф `trial`
  нужного типа.
- Если клиент уже занимался, используется активный групповой тариф `single`.
- Название тарифа и сумма копируются в заявку. Последующая правка прайса не меняет
  уже созданные заявки и подтверждённые платежи.
- Бартерных клиентов бот не записывает: им предлагается связаться с Натальей.

## Места и защита от двойной записи

Свободные места считаются так:

```text
вместимость - записанные в CRM - активные временные брони
```

Офлайн по умолчанию — 8 мест, онлайн — 20. Клиент видит число свободных мест
только когда осталось 3 или меньше. Создание брони и подтверждение оплаты повторно
проверяют лимит занятия.

Если чек не отправлен вовремя, бронь получает статус `expired`, место освобождается.
После отправки чека бронь остаётся до проверки, но не дольше начала занятия.

## Проверка подписки

В CRM в разделе «Бот» указываются:

- `@username` канала или его числовой `chat_id`;
- ссылка на канал.

Для надёжной проверки через `getChatMember` бот должен быть администратором канала.
Если оба поля пустые, проверка подписки отключена.

## Настройки в CRM

Раздел `/bot` хранит:

- включён ли клиентский режим;
- приветствие;
- текст о тренажёре;
- канал и ссылку;
- реквизиты для оплаты;
- общий адрес офлайн-зала;
- общую ссылку на онлайн-занятие;
- время удержания места.

Ниже расположен редактор сообщений и кнопок. Он разбит на группы:

- профиль бота и пост в канале;
- главное меню;
- запись на занятие;
- подписка;
- «Мои занятия»;
- прайс;
- оплата;
- напоминания.

Динамические сообщения используют переменные вида `{{date}}`, `{{amount}}`,
`{{format}}`, `{{address}}`. Их названия менять или удалять не нужно — при отправке
бот заменяет их реальными данными. Callback-команды остаются внутренними и не зависят
от видимой подписи, поэтому кнопку можно переименовывать безопасно.

Чтобы загрузить или заменить видео, Данила или Наталья отправляют видео самому боту
с подписью `/тренажер`. Бот сохраняет Telegram `file_id`, поэтому отдельное файловое
хранилище на сервере не требуется.

У конкретного занятия можно задать собственную ссылку или адрес. Они имеют приоритет
над общими настройками.

## Данные

- `BotSettings` — одна запись с настройками бота.
- `BotBooking` — заявка, сумма, чек, статус проверки и отметки напоминаний.
- `BotSession` — ID последнего экрана в чате, который бот заменяет при навигации.
- `BotContent` — изменённые через CRM тексты и подписи кнопок.
- `BotChannel` — название канала, Telegram chat ID и ID опубликованного поста.
- `Client` — создаётся или находится по стабильному Telegram ID/username.
  При первом сообщении бот запрашивает доступную фотографию профиля через
  `getUserProfilePhotos` и сохраняет только Telegram `file_id`. Браузер получает фото
  через защищённый маршрут CRM, поэтому токен бота не раскрывается.
- `Attendance` — создаётся только после подтверждения оплаты или сразу при записи
  по действующему абонементу.

Приветственное изображение лежит в `public/bot-welcome.png`. При первой отправке
бот загружает его в Telegram и сохраняет полученный `file_id` в `BotSettings`.
Аватар профиля лежит в `public/bot-profile.jpg` и устанавливается автоматически,
если у бота ещё нет фотографии профиля.

Обложки основных разделов:

- `public/bot-booking.jpg` — запись и выбор расписания;
- `public/bot-my-lessons.jpg` — «Мои занятия»;
- `public/bot-trainer.jpg` — тренажёр;
- `public/bot-prices.jpg` — прайс.

При первом открытии бот также загружает их в Telegram и сохраняет `file_id`.
Раздел тренажёра может состоять из обложки, текста и видео. `BotSession` хранит
все ID такого экрана, поэтому при переходе в другой раздел удаляется весь блок.

Статусы заявки:

| Статус | Значение |
|---|---|
| `awaiting_receipt` | место удерживается, ждём чек |
| `review` | чек у администраторов |
| `confirmed` | оплата подтверждена, клиент записан |
| `rejected` | зарезервировано для окончательного отказа |
| `expired` | срок брони или время занятия истекли |
| `cancelled` | клиент выбрал другое занятие или отменил бронь |

## Локальный тест

```bash
npm run local:setup  # отдельная SQLite-база с тестовыми клиентами
npm run local:crm    # CRM: http://localhost:3002
npm run local:bot    # бот работает через ноутбук
```

`local:bot` удаляет production webhook и включает polling. Пока процесс не запущен,
бот не отвечает. Тестовые реквизиты должны явно содержать фразу «деньги не переводить».

## Постоянный запуск на сервере

На сервере CRM и бот работают отдельными systemd-службами:

```bash
systemctl status natalivm-crm
systemctl status natalivm-bot
systemctl enable --now natalivm-bot
```

До финального переключения `natalivm-bot` должен оставаться выключенным: рабочие события
принимает webhook старого Vercel. Запуск polling удаляет webhook. Polling-процесс раз в
минуту проверяет истёкшие брони и напоминания. Одновременно держать включёнными webhook и
polling нельзя.

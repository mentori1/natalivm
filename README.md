# Наташа · кабинет преподавателя танцев

Мини-CRM для преподавателя танцев. Ядро — **карточка клиента** и **управление абонементами**,
а не воронка продаж. Главный экран показывает, кому пора продлевать и кто пропал.

**Статус:** основной рабочий контур — собственный сервер с локальным PostgreSQL.
Старый адрес Vercel перенаправляет в новую CRM, Supabase сохранён как замороженная
резервная копия на момент перехода (см. [ПЕРЕНОС-НА-СЕРВЕР.md](ПЕРЕНОС-НА-СЕРВЕР.md)).

## Возможности

- **Дашборд** — «Требуют внимания» (мало занятий / скоро срок / был на пробном / пропал /
  отходил 2 абонемента, но не купил тренажёр), занятия на сегодня, финансы месяца и прогноз выручки.
- **Клиенты** — список с фильтром по статусу и поиском по имени, телефону, Telegram username
  и Telegram ID; карточка с контактами, источником лида
  (+ «от кого»: блогер/канал/кампания), статистикой (посещения, сумма покупок, последнее занятие),
  целями, заметками, рекомендациями для преподавателя, отметкой тренажёра и удалением.
  Если клиент взаимодействовал с Telegram-ботом, его открытая фотография профиля
  автоматически сохраняется в карточке по стабильному Telegram ID.
- **Абонементы** — любое число занятий (по умолчанию 4), онлайн/офлайн, истечение по занятиям или
  по сроку, заморозка с датой и причиной. На странице абонемента: календарь посещений (отметка по дням),
  ручная правка использованных занятий, история. При покупке индивидуального абонемента можно сразу
  выбрать даты и время тренировок: CRM создаст отдельные индивидуальные занятия и запишет на них клиента.
  Остаток и статус считаются автоматически.
- **Разовые и пробные визиты** — без абонемента, оплата за визит (пробное онлайн 500 / офлайн 1000,
  разовое 2300). Считаются в посещениях и в доходах.
- **Тренажёр** — отметка покупки в карточке; напоминание предложить тем, кто отходил 2 абонемента.
  Прибыль фиксируется в момент продажи: у старых продаж остаётся сохранённая сумма, для новых
  по умолчанию подставляется 5000 ₽.
- **Занятия и посещаемость** — создание и редактирование названия, даты, формата и типа занятия,
  запись клиентов, отметка «была / не была». В новое групповое онлайн- или офлайн-занятие
  автоматически добавляются клиентки с действующим незамороженным групповым абонементом
  соответствующего типа; индивидуальные абонементы в автозапись не попадают. «Была»
  списывает 1 занятие; автоматическая запись сама по себе ничего не списывает.
  Бартерные клиентки добавляются только вручную, занимают место в группе и не создают доход.
- **Финансы** — по месяцам (переключатель ‹ месяц ›): выручка (абонементы + разовые/пробные +
  прибыль с тренажёров), расходы по категориям (аренда зала, оборудование, реклама… можно вписать свою),
  прибыль. Отдельный блок «Сейчас»: средний чек, активные, ждут продления, прогноз.
- **Источники лидов** — аналитика за период: сколько лидов и сколько из них дошли до покупки
  по каждому источнику и по каждому блогеру.
- **Вход по паролю** — одна учётка преподавателя, сессия в подписанной куке, помнит вход год.
- **Мобильная навигация** — единая Liquid Glass линза пружинно перемещается между разделами
  и меняет ширину под активный пункт; нижнее меню учитывает безопасную область экрана телефона.
- **Telegram-бот** — приветственное изображение с подписью и постоянное меню рядом
  со строкой ввода: запись, «Мои занятия», актуальный прайс из CRM и видео о тренажёре.
  Бот принимает чек PDF/фото,
  отправляет его на ручную проверку и напоминает клиенту о подтверждённом занятии.
  В разделе CRM «Бот» редактируются подписи кнопок, тексты экранов, оплаты и напоминаний.
  У разделов записи, занятий, тренажёра и прайса закреплены отдельные фирменные обложки.
  Профиль бота получает описание и аватар до нажатия «Старт». Команда `/закрепить`
  в канале публикует и закрепляет пост с кнопкой «Записаться»; переход из канала
  сохраняется в карточке нового клиента как источник.

  Клиентский бот работает на новом сервере в режиме polling. Старый Vercel webhook отключён,
  очередь Telegram при переключении была сохранена. Реквизиты оплаты, адрес офлайн-занятий
  и ссылка на онлайн-занятие задаются преподавателем в разделе CRM «Бот».

## Стек

- Next.js 16 (App Router, Turbopack) + React 19 + TypeScript
- Tailwind CSS v4
- Prisma 7 + PostgreSQL через driver adapter `@prisma/adapter-pg`
- PostgreSQL 17 на собственном сервере; Supabase сохранён как резерв старого контура
- Развёртывание: собственный сервер с nginx + systemd; старый Vercel только перенаправляет
- Авторизация — своя, на HMAC-подписи (Web Crypto, edge-совместимая)
- Шрифт Manrope (кириллица), mobile-first

## Данные (модели)

`Client`, `Subscription`, `SubscriptionVisit`, `SingleVisit`, `Lesson`, `Attendance`,
`Note`, `ClientGoal`, `Expense`, `PriceItem`, `BotSettings`, `BotBooking`, `BotSession`,
`BotContent`, `BotChannel`.
Полная схема — [`prisma/schema.prisma`](prisma/schema.prisma).
Статусы хранятся строками; «живой» статус абонемента (активен / скоро / закончился) и клиента
считается на лету в [`src/lib/domain.ts`](src/lib/domain.ts).

## Переменные окружения

| Переменная | Зачем | Где взять |
|---|---|---|
| `DATABASE_URL` | подключение к Postgres | локальный PostgreSQL на сервере или Supabase для старого контура |
| `APP_PASSWORD` | пароль входа преподавателя | задаёте сами |
| `AUTH_SECRET` | подпись сессии | `openssl rand -hex 32` |
| `TELEGRAM_BOT_TOKEN` | доступ к клиентскому Telegram-боту | BotFather, хранить только в env |
| `TELEGRAM_ADMIN_IDS` | кто может подтвердить или отклонить чек | числовые Telegram ID через запятую |
| `TELEGRAM_DROP_PENDING_UPDATES` | удалять ли очередь при запуске polling | `0`; значение `1` только для отдельного тестового бота |
| `TELEGRAM_WEBHOOK_SECRET` | защита production webhook | `openssl rand -hex 32` |

Локально лежат в `.env` (`DATABASE_URL`) и `.env.local` (`APP_PASSWORD`, `AUTH_SECRET`).
Эти файлы **не в git** (секреты). Шаблон со значениями-заглушками — [`.env.example`](.env.example).

## Безопасность старого Supabase

CRM не отдаёт Supabase-ключи в браузер: приложение работает через серверное подключение
`DATABASE_URL`. На публичных таблицах Supabase должен быть включён RLS, чтобы `anon`/public API
не мог читать, менять или удалять данные напрямую.

Проверить и включить RLS на CRM-таблицах:

```bash
npx tsx scripts/security/enable-rls.ts
```

Скрипт не печатает секреты, только состояние таблиц до/после.

## Локальный запуск старого контура

```bash
npm install
npm run dev        # http://localhost:3000
```

Локальный `.env` может быть подключён к резервной Supabase-базе. После перехода это не
рабочий источник данных: не вносить туда реальные изменения и не использовать такой запуск
вместо серверной CRM.

## Изолированный локальный тест бота

Самый простой запуск — двойной клик по файлу:

```text
/Users/mentori/НАТАША/Запустить локальную CRM и бота.command
```

После запуска окно Terminal можно закрыть: CRM и бот продолжат работать независимо
от Codex. Для остановки используется соседний файл
`Остановить локальную CRM и бота.command`. Повторный запуск не очищает локальные данные.
В изолированном локальном режиме пароль отключён; рабочий сервер по-прежнему использует
`APP_PASSWORD`.

Эти команды не используют рабочую Supabase-базу:

```bash
npm run local:setup  # создаёт dance-crm-test.db с тестовыми данными
npm run local:crm    # http://localhost:3002
npm run local:bot    # Telegram polling через ноутбук
```

`local:bot` разрешено запускать только с отдельным тестовым токеном. Рабочий бот уже запущен
на сервере; второй polling-процесс с тем же токеном будет конфликтовать с ним.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер |
| `npm run build` | продакшн-сборка |
| `npm run start` | запуск собранной версии |
| `npm run db:push` | применить изменения схемы к базе |
| `npm run db:studio` | визуальный редактор базы (Prisma Studio) |
| `npm run local:setup` | пересоздать отдельную локальную тестовую базу |
| `npm run local:crm` | локальная тестовая CRM на порту 3002 |
| `npm run local:bot` | локальный бот с тестовой SQLite-базой |
| `npm run bot:poll` | постоянный polling-бот с базой из `DATABASE_URL` |

> ⚠️ **`npm run db:seed` и `npm run db:reset` НЕ запускать на проде** — они затирают базу
> тестовыми данными. Сейчас в базе реальные клиенты Наташи.

## Структура

```
prisma/schema.prisma     модель данных
src/lib/db.ts            Postgres в работе / SQLite в локальном тесте
src/lib/domain.ts        бизнес-логика (статусы, остатки, цены, напоминания)
src/lib/queries.ts       запросы к БД (дашборд, списки)
src/lib/actions.ts       server actions (создание/изменение)
src/lib/auth.ts          подпись сессии; auth-actions.ts — вход/выход
src/middleware.ts        проверка входа на каждый запрос
src/app/                 страницы (дашборд, клиенты, занятия, абонементы, финансы, источники, вход)
src/components/          UI-компоненты
```
